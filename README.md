# Pranam Software — website

Multi-page marketing site for Pranam Software, built on the stack you specified.
The visual design is unchanged from the approved single-page version — the CSS was
lifted across verbatim into `src/styles/app.css`.

## Stack

| Layer      | What's used                                              |
|------------|----------------------------------------------------------|
| Framework  | TanStack Start (SSR) + React 19 + TypeScript              |
| Routing    | TanStack Router, file-based (`src/routes`)                |
| Styling    | Tailwind CSS v4 (`@tailwindcss/vite`) + the project's own design CSS |
| Components | shadcn/ui conventions (`components.json`, `cn()` helper)  |
| Data       | Supabase — auth-ready client + project inquiries table    |
| Images     | Cloudinary unsigned upload + delivery helpers             |
| Hosting    | Vercel                                                    |

## Pages

| Route       | Contents                                                        |
|-------------|-----------------------------------------------------------------|
| `/`         | Hero, intro video, brands, services, process, 3 featured products, testimonials, hire CTA |
| `/about`    | Story, feature icons, certifications, brands                    |
| `/services` | All six service cards + the process timeline                     |
| `/products` | Full product grid + testimonials                                 |
| `/process`  | Four-step process + intro video block                            |
| `/team`     | All six team members + testimonials                              |
| `/contact`  | Project inquiry form (writes to Supabase) + contact cards        |

## Getting started

```bash
npm install
cp .env.example .env      # fill in your keys
npm run dev               # http://localhost:3000
```

`src/routeTree.gen.ts` is generated by the TanStack Router plugin the first time you
run `npm run dev` or `npm run build`. It is gitignored on purpose — don't hand-edit it.
Type errors about that file before the first run are expected.

## Supabase

1. Create a project at supabase.com.
2. Run `supabase/migrations/0001_project_inquiries.sql` in the SQL editor.
3. Copy the project URL + anon key into `.env`, and the **service role** key into
   `SUPABASE_SERVICE_ROLE_KEY` (no `VITE_` prefix — it must never reach the browser).

The contact form posts through a TanStack **server function** (`src/server/inquiries.ts`),
so the service key stays server-side and RLS keeps the inbox private. Read submissions
from the Supabase table editor, or build an authenticated `/admin` route later using the
browser client already exported from `src/lib/supabase.ts`.

## Cloudinary

1. Create an **unsigned** upload preset (Settings → Upload → Upload presets).
2. Put the cloud name + preset name in `.env`.
3. `uploadImage(file)` uploads from the browser; `cld(publicId, width)` builds an
   `f_auto,q_auto` delivery URL.

To replace the stock photos: upload your real team headshots and product screenshots,
then swap the `img` URLs in `src/data/site.ts` for the Cloudinary URLs. Every image
falls back to a styled initials plate if a URL is missing, so nothing ever looks broken.

## Editing content

All copy — services, products, team, testimonials, nav, contact details — lives in
`src/data/site.ts`. Pages are presentational; you shouldn't need to touch JSX to change
a phone number or add a product.

## Tailwind note

`src/styles/app.css` imports Tailwind's **theme and utilities only**, not Preflight.
That is deliberate: Preflight's reset would fight the hand-written design. Tailwind
utility classes (`mt-7`, `flex`, `gap-4`, …) work everywhere. If you later want the full
reset, replace the two imports at the top of the file with `@import "tailwindcss";` and
re-check the hero, form and footer spacing.

## Deploy to Vercel

```bash
npm i -g vercel
vercel            # first deploy, links the project
vercel --prod
```

Add the same four `VITE_*` variables plus `SUPABASE_SERVICE_ROLE_KEY` under
Project → Settings → Environment Variables. Vercel detects the Vite build; output is
`.output`. No extra config file needed.

## Note on versions

This project was authored against TanStack Start v1 (the `@tanstack/react-start`
Vite-plugin setup). Dependencies were not installed in the environment where it was
generated — the npm registry was unreachable there — so run `npm install` and
`npm run dev` once and fix any version drift at the top of `vite.config.ts` /
`src/routes/__root.tsx` if your installed Start version expects a different entry shape.
Everything else (components, styles, data, Supabase, Cloudinary) is framework-version
independent.
